Homework 13-1: Robust File Transfer with Length-Prefix Framing

Objective

Build a file transfer application that uses length-prefix message framing (from Lecture 13.1) to reliably send and receive files between a server and client. This assignment tests your understanding of message framing, buffer management, and progress tracking.

Requirements

Part A: MessageBuffer Class

    Implement the MessageBuffer class from Lecture 13.1 with append(), hasCompleteMessage(), and nextMessage() methods.
    Use a 4-byte (quint32) length prefix in network byte order (QDataStream).
    Handle edge cases: empty messages, messages split across multiple readyRead calls.

Part B: File Transfer Server

    Create a QTcpServer that accepts file uploads from clients.
    Use the MessageBuffer class to receive length-prefixed messages.
    Support a simple protocol: client sends a FILE_INFO message (filename + size), then the file data as one or more DATA messages, then a TRANSFER_COMPLETE message.
    Save received files to a configurable output directory.
    Log all events with timestamps (connection, file start, progress, completion).

Part C: File Transfer Client GUI

    Create a client GUI with: Connect button (host + port), Browse button (QFileDialog to select a file), Upload button, QProgressBar showing transfer progress, QTextEdit log showing events.
    Send files using the length-prefix protocol from Part B.
    Update the progress bar as bytesWritten() fires.
    Disable Upload button during transfer.

Part D: Error Handling and Timeouts

    Add a 30-second connection timeout using QTimer.
    Handle server disconnection during transfer (show error, reset UI).
    Validate: prevent uploading when not connected, prevent uploading empty files.
    Show QMessageBox for all errors.

Homework 13-2: Secure Chat Application with SSL/TLS

Requirements

Part A: Secure Server

    Generate a self-signed SSL certificate and private key using OpenSSL (include the files in your submission).
    Modify the ChatServer to upgrade incoming TCP connections to SSL using QSslSocket.
    Load the certificate and key files, and call startServerEncryption() for each new client.
    Only allow clients to chat after the encrypted() signal fires (reject unencrypted clients).
    Add a server GUI showing a log with a green "SSL" indicator for encrypted connections.

Part B: Secure Client (15 points)

    Modify the ChatClient to use QSslSocket with connectToHostEncrypted().
    Handle the sslErrors signal: display certificate details and let the user choose to trust or reject.
    Show the connection security status in the client GUI ("Connected (Encrypted)" in green vs "Connected (Plain)" in orange).
    Display the SSL cipher name in the status bar after connection.

Part C: Message Framing Upgrade (10 points)

    Replace the newline-delimited framing from Chapter 12 with length-prefix framing using the MessageBuffer class from HW1.
    Verify that messages containing newlines are transmitted correctly (this would break the old delimiter-based framing).
    Ensure the protocol still supports JOIN, MSG, QUIT, CHAT, JOINED, LEFT, USERLIST commands.

Part D: Testing and Documentation (10 points)

    Test with 2+ clients connected simultaneously via SSL.
    Include a screenshot showing the encrypted connection indicator.
    Include a screenshot showing the server log with SSL connections.
    Write a brief README (5-10 sentences) explaining what changes you made from the Chapter 12 version and why SSL/TLS matters.
